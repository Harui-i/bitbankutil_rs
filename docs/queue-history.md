# 長期backtestのqueue履歴

`PaperExecutionEngine::queue_diagnostics()` は、キューの内容を複製せず、
生存自注文を持つ価格数 (`active_levels`)、保持する全価格数 (`retained_levels`)、
数量または自注文を持つ価格数 (`queue_levels`)、segment数、生存自注文数、
除去したsegmentの累計を返す。数量を持つlevelと生存注文の走査は行う。
`settlement_status()` の `queue_diagnostics` にも同じ情報を載せる。
`queue` の詳細コピーは数量または自注文を持つ価格だけをside/price順に返す。

## 保持する根拠

自注文IDがなく、外部数量が0のsegmentは除去する。最後のsegmentを除去した価格は、
最終表示数量だけを持つ別のmapへ移す。次の注文を受け付けても現在板から外部数量を
初期化し直さない。新しい板で表示数量が増えたときだけ、その差分を従来どおり末尾へ追加する。
表示減少を先頭数量の減少へ置き換えない。

数量を持つ価格はside/price順のmapで検索し、取消は注文IDから所属価格を検索する。
板更新は新しい板の表示価格と、直前の表示数量が正だった保持価格だけを処理する。
空になった過去価格を約定検索・板更新・詳細コピーで総走査しない。

空価格の根拠自体は価格数に比例して残る。watermarkが進んでも削除しない。
根拠を削除すると、将来の受付で消化済み数量を復活させたり、次の表示増加の有効化時刻を
受付時刻へ変えてしまう。watermarkは公開約定の封鎖境界であり、板の将来の再登場を
禁止するものではない。正の数量は有効化時刻が異なれば合算しない。
この変更は無制限の全履歴を定数メモリへ変えるものではなく、不要な0数量履歴と
その走査・コピーを取り除く。

## 独立した合成benchmark

外部API、記録、口座照会を使わずQueueModelだけを比較する。
`benches/queue_history.rs` は現行実装と、commit `6581cfab` の旧実装を別プロセスで実行する。
比較専用の旧実装は `src/paper_execution/queue/legacy.rs` に保持し、通常のライブラリには含めない。

```sh
cargo bench --locked --bench queue_history -- old 1000 8
cargo bench --locked --bench queue_history -- new 1000 8
cargo bench --locked --bench queue_history -- old 5000 8
cargo bench --locked --bench queue_history -- new 5000 8
cargo bench --locked --bench queue_history -- old 1000 32
cargo bench --locked --bench queue_history -- new 1000 32
```

引数は旧/新、過去価格数、価格ごとの表示増減回数。生存自注文は1件に固定する。
履歴用の買い価格で表示数量を増減し、注文受付・取消・公開約定による外部数量消化を繰り返す。
構築後は板更新、同価格への受付・取消、価格通過のallocation、詳細stateコピーを各200回測る。

出力は処理時間、allocator呼出回数、累積要求byte、処理後の生存heap byte、処理中の最大heap byteを
処理別に分ける。最大RSSはLinuxの `/proc/self/status` の `VmHWM`。
allocatorはSystemへの要求サイズを数え、allocatorの内部管理領域やスタックは数えない。
RSSはそれらも含み、起動や診断取得を含めたプロセス全体の最大値である。
測定用のatomicカウンタのコストは両実装に含まれる。

追加の保持価格2件は生存売注文の価格と測定用の再受付価格。
5,000 / 8の構築後の生存heapは旧2,126,910 byte、新355,134 byte。
構築中のallocator呼出回数は旧335,011回、新431,657回、累積要求量は旧67,288,064 byte、
新85,847,428 byteであり、この部分は増える。履歴を保持し続けるVecから短命なmap/segmentへ
変えた結果であり、allocation自体がすべての処理で減るという結果ではない。
[生の出力](benchmarks/)には処理別の全数値を残す。
実際のbacktest全体に対する寄与や速度倍率はこの測定からは断定しない。

## 同等性の検証

- 比較専用の旧QueueModelと、固定seed12個・各1,200操作の板更新/受付/取消/成立時刻が前後する
  約定を比較する。allocationと、0数量segmentを除いたキュー状態を各操作後に照合する。
- `tests/paper_queue.rs` の履歴シナリオでは、時計差±250ms/0、記録有無、watermark分割有無を組み合わせる。
  取消と再受付、価格通過、表示増減、遅着・重複約定、開始/取消と同msの約定を含む。
  `fixtures/queue_history_023.json` は旧commitのソースを別ディレクトリへ展開し、同じシナリオで
  採取した注文・約定・手数料・残高・拒否理由。新実装の出力と一致することを確認する。
- 既存テストでも公開約定数量の共有上限、FIFO、有効期間、watermark分割による結果の一致を確認する。
